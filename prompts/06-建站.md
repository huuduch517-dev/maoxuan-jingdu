# 提示词 06 · 建站

> **用法**：内容攒到二十篇以上再做。开新会话，整段粘贴。

---

用 **VitePress** 把 `docs/` 下的内容做成静态站。

选 VitePress 的理由（不要换）：中文全文搜索开箱即用；自定义容器（`::: tip / warning / info`）正好对应本项目的「一个细节 / 存疑 / 不同看法」三类标注；内容全在 Markdown 里，改文章不碰代码。

## 一、基础配置

`docs/.vitepress/config.ts`：

- `lang: 'zh-CN'`，站名「毛选精读」
- 启用本地全文搜索（`themeConfig.search.provider = 'local'`，中文分词按 VitePress 文档配好）
- 侧边栏**不要手写**，从 `data/catalog.yaml` 动态生成
- 暗色模式跟随系统

## 二、三套导航入口（这是重点）

同一批内容必须有三条进入路径，因为三种读法不一样：

**1. 按篇目** —— 按卷次分组，每条显示：篇名 · 年份 · 难度 · 主题标签。
默认按卷次，可切换按时间排序。

**2. 按主题** —— `docs/主题/` 下的串讲页。每个主题页顶部列出该主题下的篇目卡片。

**3. 按金句** —— 从 `data/quotes.yaml` 生成一个可筛选的金句页：
   - 按主题、卷次筛选
   - 每条金句默认只显示原句和出处，点开才展开「当时指什么 / 常见误读 / 还剩下什么」
   - **「常见误读」用视觉上明显区别的样式**（比如左边框加色），这是全站最想让人看见的东西
   - 点击跳转到出处篇目的对应位置

## 三、单篇页面

- 右侧目录（六节）常驻
- 三类自定义容器的样式要**明显区分**：
  - `tip`（一个细节）—— 正向、醒目
  - `warning`（存疑）—— 警示色，让人一眼知道这里不确定
  - `info`（不同看法）—— 中性
- frontmatter 里的 `prerequisite` 渲染成页面顶部的「建议先读」提示条
- 「互文」一节的链接做成卡片
- 页面底部显示 `applies_to` 标签

## 四、首页

不要做营销页。做成一个**学习控制台**：

- 进度：已完成 N / 38 篇
- 三条推荐路径（各 5–8 篇，给出顺序和一句话理由）：
  - 「先建立思维底座」（认识论为主）
  - 「管理与组织」
  - 「长期判断力」
- 随机抽一条金句（含「常见误读」）
- 最近更新的三篇

## 五、一个必须做的功能：存疑索引

单独一页 `docs/存疑索引.md`，自动汇总全站所有 `::: warning 存疑` 块，按篇目归类，注明待核对的方向。

这一页是这个项目的诚实度仪表盘，也是我人工核对时的工作清单。**不要省略。**

## 六、不要做的

- 不要做评论、点赞、分享
- 不要引入任何统计或追踪脚本
- 不要做登录
- 不要为了炫技加动画

## 七、交付

- `npm run docs:dev` 本地可跑
- `npm run docs:build` 产物在 `docs/.vitepress/dist`
- 写一个 `部署说明.md`：怎么本地跑、怎么加一篇新文章、怎么部署到静态托管
- 把「加一篇新文章的步骤」写清楚——这是我以后最常做的操作
