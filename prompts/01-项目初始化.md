# 提示词 01 · 项目初始化

> **用法**：在项目根目录（已放好 `CLAUDE.md` 和 `sources/`）开一个新会话，整段粘贴。只跑一次。

---

先读 `CLAUDE.md`，确认你理解了项目定位、三条红线和单篇结构规范。然后执行下面四件事，**不要开始写任何解读内容**。

## 一、盘点原始材料

扫描 `sources/` 目录，搞清楚：

1. 有哪些文件，各是什么格式，覆盖哪几卷
2. 文本是否完整（有无缺页、乱码、OCR 错误）
3. 是否带有原书的**脚注和题解**——这些注释是史实考证的第一手依据，比你的记忆可靠得多，务必确认它们有没有被保留下来
4. 文本编码、分卷方式、单篇之间的分隔标记是什么

把结果写成 `sources/_清单.md`，如实标出有问题的文件。**如果某一卷缺失或质量差，明确说出来，不要含糊带过。**

## 二、建立篇目索引 `data/catalog.yaml`

从 `sources/` 中提取全部篇目，每篇一条：

```yaml
- slug: 论持久战
  title: 论持久战
  volume: 2
  date: "1938-05"        # 以原文标注为准；原文未标则留空，不要推测
  date_source: 原文标注   # 原文标注 / 目录页 / 未知
  path: sources/卷二/论持久战.md
  wordcount: 50000
  in_shortlist: true      # 是否属于第一期精选
```

**date 字段只填原文里有的**。原文没标时间的，留空，`date_source` 写"未知"。这是红线一的具体执行。

## 四、建立主题词表 `data/themes.yaml`

浏览精选篇目的标题和开头，归纳出 **8–12 个主题标签**，作为全站唯一的主题词表（`CLAUDE.md` 规定 frontmatter 的 `themes` 只能从这里选）。

要求：

- 标签要**能切分内容**，不要用"思想方法"这种覆盖一切的大词
- 面向本项目的两个应用场景（职场与管理、个人决策与认知）来切，不要按党史分期切
- 每个标签给一句话定义和 3–5 篇代表篇目

先把你的初稿给我看，**我确认后再写入文件**。

## 五、建立 `PROGRESS.md`

完成后，用不超过 300 字向我汇报：材料完整度、篇目对不上的地方、主题词表初稿、以及你认为**从哪一篇开始做样板最合适**（并说明理由）。

不要开始写解读。
