# 《毛选》深度解读学习站 — Claude Code 提示词套件

## 这套东西解决什么问题

让 Claude Code 写三十几篇长文，写得出来不难，难的是**写到第二十篇还没崩**。批量生成长内容有四个固定的死法：

| 死法 | 表现 | 本套件的对策 |
|---|---|---|
| **史实漂移** | 编造会议名称、日期、数字、引文，且语气笃定 | 史实考证与解读写作**分成两轮**，中间产出可核对的 `research/` 笔记；`[存疑]` 标注制度 |
| **鸡汤化** | "读懂这一句，你就读懂了半本毛选" | 禁用词表 + 强制写「迁移边界」和「常见误用」两节 |
| **模板化** | 三十篇读起来像同一篇填空 | 单篇结构固定但**篇幅配额浮动**；每篇必须有一条只属于这篇的"反直觉发现" |
| **上下文爆炸** | 一次喂四卷，后面越写越糊 | 一篇一会话，`PROGRESS.md` 做跨会话交接 |

## 目录结构

把这些文件放进你的项目根目录：

```
maoxuan-study/
├── CLAUDE.md              ← 项目宪法，Claude Code 每次自动读取
├── prompts/               ← 你手动粘贴的六个提示词
│   ├── 01-项目初始化.md
│   ├── 02-史实考证.md
│   ├── 03-单篇解读.md
│   ├── 04-质检.md
│   ├── 05-金句库与主题串讲.md
│   └── 06-建站.md
├── sources/               ← 你的电子版原文（只读，Claude 不许改）
├── research/              ← 史实考证笔记（中间产物）
├── docs/                  ← 网站内容（VitePress 根目录）
├── data/                  ← catalog.yaml / quotes.yaml
└── PROGRESS.md            ← 进度台账
```

## 操作顺序

**阶段零 · 一次性**
1. 建目录，把电子版丢进 `sources/`，把 `CLAUDE.md` 放到根目录
2. 粘贴 `prompts/01-项目初始化.md` → 得到 `data/catalog.yaml` 和 `PROGRESS.md`

**阶段一 · 样板篇（重要，别跳过）**
3. 挑《论持久战》做第一篇，完整走一遍 `02 → 03 → 04`
4. **亲自读一遍产出**，把你不满意的地方直接改进 `CLAUDE.md`。这一步花掉的一小时，抵后面三十篇的返工

**阶段二 · 流水线**
5. 每篇开一个新会话（`/clear` 或新窗口），依次跑 `02 → 03 → 04`
6. 每五篇停一次，回头抽读一篇早期的，看质量有没有滑坡

**阶段三 · 组装**
7. `prompts/05` 抽金句库和主题串讲（必须等篇目攒够二十篇以上再做，不然主题串讲没料）
8. `prompts/06` 建站

## 节奏建议

- 单篇三轮下来大约消耗不少上下文，**一个会话只做一篇**，做完就清
- 不要为了赶进度跳过质检轮。质检轮是这套流程里性价比最高的一环
- 三十八篇不要一口气跑完。按主题分四批，每批之间自己先读一遍，调整 `CLAUDE.md`

## 一个提醒

这套提示词把「不确定就标注存疑」写成了硬规则。你会在成稿里看到一些 `[存疑]` 块——这是设计意图，不是失败。看到它就说明模型在那里本来要编，被拦下来了。真要坐实，自己去查《毛泽东年谱》或原文注释，比让模型硬编强。
